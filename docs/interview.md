# Шпаргалка к собеседованию: «Летучка»

## Vue

**Чем Vue отличается от React?**
Реактивность на прокси: Vue сам отслеживает, какие данные читал шаблон или
`computed`, и обновляет ровно их — без массивов зависимостей. `<script setup>`
выполняется один раз, а не на каждый рендер, поэтому не нужны
`useCallback`/`useMemo` для стабильности функций. Шаблоны с директивами вместо JSX.

**ref или reactive?**
`ref` — для любого значения, доступ через `.value` в скрипте; `reactive` — для
объектов, без `.value`, но его нельзя деструктурировать и переприсвоить
целиком. В проекте везде `ref` — одно правило.

**computed и watch?**
`computed` — производное значение с кешем (аналог `useMemo`). `watch` — побочный
эффект при изменении (аналог `useEffect` с зависимостью): переподключение к
комнате при смене id.

**Как компонент сообщает родителю?**
`defineEmits` и `emit('submit', name)`; родитель слушает `@submit`. Данные вниз
пропсами, наверх — событиями.

**Что такое nextTick?**
Vue обновляет DOM пачкой в микрозадаче; `await nextTick()` — дождаться
обновления (фокус в только что появившееся поле).

## Nuxt

**Зачем Nuxt?**
Маршруты из файлов, авто-импорты, настройки и модули, SSR/SSG при
необходимости. Здесь `ssr: false`: SPA на GitHub Pages, данные из Supabase.

**runtimeConfig.public?**
Настройки, переопределяемые переменными окружения
(`NUXT_PUBLIC_SUPABASE_URL`). Всё в `public` попадает в браузер.

## Бэкенд и безопасность

**Если ключ Supabase в браузере, кто защищает данные?**
Row Level Security: правила в Postgres проверяют каждую строку каждого запроса.
Карточки создаёт только автор и только на этапе «пишем»; лимит 3 голоса —
подсчёт в правиле, его не обойти запросом в обход интерфейса. Секретный ключ
(service_role) обходит RLS и в браузер не попадает никогда.

**Как сделан вход без регистрации?**
Анонимный вход Supabase: настоящий пользователь с токеном, но без почты.
Имя — в `user_metadata`.

**Как устроен realtime?**
Действие → запись в базу (RLS) → Broadcast изменения в канал комнаты; у всех
изменение проходит через одну чистую функцию `applyChange`. Presence — список
участников онлайн. Курсоры и реакции — эфемерный Broadcast без базы.

**Почему таймер не рассылает тики?**
Хранится момент окончания, каждый клиент считает остаток сам: одно сообщение,
одинаково у всех, не зависит от задержек сети.

**Как разрабатывать без сервера?**
Интерфейс `Backend` и две реализации: локальная (localStorage +
BroadcastChannel между вкладками) и Supabase. Компоненты не знают, какая
подключена; локальная же используется в интеграционных тестах.

**Что слабое место и как улучшить?**
Скрытые карточки скрыты только в интерфейсе — для настоящей тайны отдавать
текст с сервера после смены этапа (view/Edge Function). Потерянное
Broadcast-сообщение — перезагружать снимок при переподключении. Дальше:
шаблоны колонок, группировка похожих карточек перетаскиванием, история ретро
команды.
